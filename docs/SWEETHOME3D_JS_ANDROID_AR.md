# اعتماد مصدر Sweet Home 3D JS لتطبيق Android العربي

تاريخ التدقيق: 2026-11-25

## القرار المعماري

المصدر المعتمد هو مشروع **Sweet Home 3D JS 7.5.2** الموجود ضمن المرآة غير الرسمية للمصدر الأصلي:

- المصدر: https://github.com/lurume84/SweetHome3D
- مجلد المحرر: `SweetHome3DJS/`
- المصدر الأساسي الذي يعتمد عليه: `SweetHome3D/`
- الترخيص: GPL-2.0 كما هو موضح في ملفات الترخيص بالمصدر.
- مرجع البناء: `SweetHome3DJS/README.TXT` و `SweetHome3DJS/build.xml`.

هذه المرآة ليست مستودعاً رسمياً للمشروع؛ وهي نسخة Git لمصدر SVN. يجب الاحتفاظ بإشعارات حقوق النشر والتراخيص وعدم وصفها بأنها مستودع رسمي.

## ما أثبته فحص المصدر

- README الخاص بـ SweetHome3DJS يعرّف الإصدار 7.5.2 بأنه عارض ومحرر HTML5 ثلاثي الأبعاد لملفات Sweet Home 3D.
- هدف Ant المسمى `applicationLibraries` يولّد مكتبات المحرر، بينما `applicationDistribution` يبني ملفات التطبيق الموزعة.
- المحرر يعتمد على أجزاء من مصدر Java الأساسي؛ لذلك لا يكفي نسخ مجلد JavaScript وحده.
- يتطلب بناء مكتبات JSweet وجود JDK 11 أو أحدث، وNode.js 14 وفق README، وAnt، مع أدوات JSweet الموجودة ضمن المصدر.
- يحتوي المصدر على `test/testHome.html` و `test/testIndexedDB.html` كنقطتي تشغيل/اختبار للمحرر وحفظ المتصفح.
- المحرر الأصلي يستخدم HTML5 وWebGL. لذلك فإن تغليفه على Android يحتاج WebView محلياً مضبوطاً، وليس استبدال المحرك بـ Canvas أو OpenGL مستقل.

## حالة مستودع Mokhatiti-3D عند بدء هذا المسار

- الفرع `main` هو نقطة انطلاق هذا المسار.
- الفرع السابق `feat/native-sweethome3d-core-port` وطلب الدمج #4 يحتويان محرراً Android مستقلاً بـ Kotlin/Canvas/OpenGL ES، ويقر وصف طلب الدمج بأنه ليس نقلاً كاملاً لـ Sweet Home 3D.
- لن تُدمج تغييرات المحرك المستقل ضمن هذا المسار، ولن تُحذف الفروع القديمة؛ تبقى محفوظة للرجوع والمقارنة.
- التطبيق الحالي على `main` يحتوي إعداد Gradle وغلاف مشروع، ولا يحتوي حتى الآن ملفات محرك Sweet Home 3D JS المجمعة أو واجهة محرر متكاملة.

## خطة الدمج والتنفيذ

### 1. تثبيت المصدر وقابلية البناء
- تثبيت مرجع upstream واضح للإصدار 7.5.2 وتسجيل commit/revision.
- جلب مصدر SweetHome3DJS مع مصدر SweetHome3D الأساسي والاعتماديات المطلوبة.
- بناء `applicationLibraries` ثم `applicationDistribution` في بيئة CI قابلة لإعادة الإنتاج.
- عدم تضمين ملفات توزيع غير مكتملة أو مكتبات مولّدة فارغة.

### 2. تطبيق Android محلي
- إنشاء شاشة Android أصلية لإدارة فتح/إنشاء المشاريع، ثم عرض محرر Sweet Home 3D JS داخل WebView محلي.
- تضمين ملفات HTML/JS/CSS والموارد محلياً داخل APK؛ لا يعتمد التشغيل الأساسي على الإنترنت أو خادم خارجي.
- ضبط WebView على WebGL وJavaScript والملفات المحلية وفق أقل صلاحيات لازمة.
- ربط Android Storage Access Framework بفتح وحفظ ملفات `.sh3d` مع دعم الاستعادة والحفظ المحلي.
- منع أي واجهة تجريبية أو صفحة اختبار من أن تصبح نقطة التشغيل النهائية.

### 3. العربية وRTL
- تحديد مصدر النصوص الفعلي: موارد Java التي يحولها JSweet، ونصوص واجهة SweetHome3DJS، وعناصر HTML.
- إضافة العربية إلى موارد اللغة بدلاً من ترجمة النصوص آلياً وقت التشغيل.
- دعم RTL في الحاويات والنوافذ والقوائم دون عكس المخطط أو الإحداثيات أو اتجاهات القياس.
- إبقاء الأرقام والقيم الهندسية والوحدات واتجاهات الأسهم الهندسية صحيحة.
- توحيد مصطلحات الجدران والغرف والأثاث والفتحات والقياسات.

### 4. تكييف اللمس والهاتف
- مراجعة أحداث pointer/touch في PlanComponent وأدوات التحرير.
- اختبار إنشاء الجدار بتحديد البداية ثم السحب/تحديد النهاية ومعاينة الخط قبل الاعتماد.
- فصل الرسم عن تحريك المشهد والتكبير بإصبعين، وضبط مناطق اللمس وحجم الأزرار.
- تكييف اللوحات والجداول والنوافذ مع الهاتف والتابلت دون تعطيل ميزات المحرر.
- إبقاء اختصارات لوحة المفاتيح/الفأرة عند وجودها، دون جعلها شرطاً للعمل باللمس.

### 5. الاختبارات وبوابة الإصدار
- بناء المحرر JS والتحقق من تحميل كل الموارد وعدم وجود أخطاء JavaScript.
- اختبارات ملفات `.sh3d`: فتح، تعديل، حفظ، إغلاق، إعادة فتح، واستعادة.
- اختبارات أدوات الجدران والغرف والأبواب والنوافذ والأثاث وتزامن 2D/3D.
- اختبارات WebGL وWebView على Android 11+، ثم على هاتف TECNO المستهدف عند توفره.
- اختبار اللمس الفعلي، تدوير الشاشة، فقدان الذاكرة، العودة من الخلفية، والعمل دون اتصال.
- إنشاء APK Release فقط بعد اجتياز بوابات القبول وتوثيق النتائج.

## قيود ومخاطر يجب اختبارها لا افتراضها

- WebGL داخل Android WebView يختلف حسب إصدار Android System WebView وتعريف GPU؛ يجب التحقق على الجهاز المستهدف.
- محرر JS 7.5.2 ليس تطبيق Android أصلياً؛ طبقة Android المطلوبة هي غلاف محلي مع تكامل ملفات وأذونات، بينما يبقى المحرك الأصلي هو Sweet Home 3D JS.
- بعض ميزات إصدار سطح المكتب قد لا تكون موجودة في نسخة JS؛ يجب إعداد مصفوفة مقارنة قبل الادعاء بتكافؤ كامل.
- لا يجوز الادعاء بدعم استيراد كل صيغ 3D أو إنشاء الصور/الفيديو ما لم تكن موجودة فعلياً في نسخة JS واختُبرت على Android.

## قاعدة الحالة

لا تُسجّل أي ميزة على أنها مكتملة إلا بعد تنفيذها واجتياز اختبار قبولها. نجاح Gradle وحده لا يثبت عمل المحرر أو WebGL أو اللمس. لا يُنشأ APK أثناء مرحلة التطوير الحالية.

## تدقيق الترجمة العربية للإصدار 7.5.2

- ملف الترجمة العربية المنشور من المشروع الأصلي هو Arabic 7.1.1، بينما المحرك المثبت هنا Sweet Home 3D JS 7.5.2. لذلك لا يجوز وصف نقل هذا الملف وحده بأنه تعريب كامل؛ قد توجد مفاتيح واجهة أضيفت بعد 7.1 وتظهر بالإنجليزية.
- أضيف السكربت `scripts/audit-arabic-properties.py` لمقارنة ملفات موارد الواجهة الإنجليزية بنظائرها العربية، والتحقق من وجود كل حزمة ومفاتيحها قبل متابعة بناء Android.
- خطوة CI المسماة `Audit Arabic translation coverage` تمنع البناء عند وجود حزم أو مفاتيح واجهة غير مترجمة. يجب استكمال أي مفاتيح تظهر في تقرير CI بصياغة عربية صحيحة، ثم إعادة تشغيل التدقيق.
- هذا التدقيق يغطي ملفات موارد `.properties` ضمن حزم الواجهة التي يستهلكها المحرك؛ ولا يغني عن مراجعة نصوص HTML/JavaScript ورسائل الأخطاء والنوافذ المنبثقة بصرياً واختبار RTL على الهاتف.
