# خطة دمج المحرك — Mokhatiti 3D

## القرار التقني
المرشح الأول هو **Sweet Home 3D JS** وليس تطبيق سطح المكتب Java/Swing. نسخة JS أقرب للدمج داخل Android عبر WebView، مع طبقة Android أصلية لتعامل الملفات والمشاركة.

مصادر:
- https://www.sweethome3d.com/
- https://www.sweethome3d.com/license/
- https://github.com/lurume84/SweetHome3D/tree/master/SweetHome3DJS

## بوابة ما قبل الدمج
1. تثبيت commit محدد من مصدر SweetHome3DJS وتسجيله.
2. مراجعة LICENSE.TXT وCOPYING.TXT وTHIRDPARTY-LICENSE-* المرفقة.
3. تحديد ناتج البناء الفعلي من build.xml وعدم افتراض أن ملفات التطوير جاهزة للتشغيل.
4. الحفاظ على إشعارات حقوق النشر والرخصة وإتاحة الشفرة المطابقة وفق GPL.
5. تدقيق تراخيص الأثاث والخامات بصورة مستقلة؛ ترخيص المحرك لا يغطي تلقائياً كل نموذج خارجي.
6. اختبار WebGL وملفات المشاريع والأداء على Android وأحجام الشاشات المختلفة.

## البنية المقترحة
- android/: تطبيق Android أصلي Kotlin.
- android/app/src/main/assets/engine/: ملفات Sweet Home 3D JS المبنية محلياً.
- android/app/src/main/assets/ui/: طبقة الواجهة العربية والتكييف اللمسي.
- docs/: توثيق الدمج والاختبارات والتراخيص.
- .github/workflows/: بناء وفحص آلي.

## متطلبات التجربة
- RTL حقيقي.
- مساحة تخطيط قابلة للتكبير والتحريك.
- أدوات الجدران والغرف والأبواب والنوافذ.
- انتقال متزامن بين المخطط 2D والمشهد 3D.
- شريط أدوات متكيف مع الهاتف والتابلت.
- حفظ محلي وفتح الملفات عبر Android Storage Access Framework.
- لا حساب ولا خدمة سحابية إلزامية.

## اختبارات قبول أول APK
- تشغيل المحرك دون اتصال بعد التثبيت.
- إنشاء جدران وغرفة وباب ونافذة.
- ظهور التعديلات نفسها في المعاينة 3D.
- حفظ مشروع وإعادة فتحه دون فقدان البيانات.
- اختبار استيراد/تصدير صيغة يدعمها المحرك.
- اختبار اللمس والتكبير والسحب على هاتف وجهاز لوحي.
- فحص سجل الأعطال وعدم وجود شاشة فارغة أو عناصر شكلية.
